## Design authority and delegated taste

Before briefing a new reference image or planning substantial frontend design, read [references/design-planning.md](design-planning.md). It routes the pre-image brief and the detailed plan based on the selected image through the current preferred planner and fallback. Implementation/review roles and human taste authority stay with their existing owners; routine repairs reuse the accepted direction.

For a new visual identity or major redesign, load [references/design-judgment.md](design-judgment.md) and use its image-led direction workflow before selecting parts. Explore coherent whole-page worlds, then derive required layouts and consequential states from the selected master. An approved identity or routine repair reuses its references and working parts without new exploration.

For the first implementation from a selected visual reference, read [references/first-draft.md](first-draft.md) before constructing parts. It owns visible construction assumptions, correction hints during production, and early bounded checks of defining relationships and motion. Routine repairs retain approved interpretations rather than reopening the whole brief.

Before retrieving missing UI parts or assets, read [references/component-selection.md](component-selection.md). It owns theme-aware resource search, premade-component reuse and showing selected parts before product integration. Search relevant resources when local components do not satisfy the selected role; do not rely on this catalog being passively loaded. Routine repairs and approved working parts need no new search.

Before choosing or delegating a visual direction or render-quality settings, load [references/personal-design-defaults.md](personal-design-defaults.md). It owns this user's reusable taste and collaboration preferences across projects, separately from the general engineering method. Current requests and an established project's explicit approvals take precedence; apply the defaults without asking the user to repeat them.

The current request and explicitly approved references lead. Preserve a coherent existing product system unless redesign is authorized; missing `DESIGN.md` does not erase the identity already present in the UI, assets, and code. Refinement fixes the named weakness while preserving approved typography, texture intensity, content order, and unrelated working qualities. Judge the changed element with its neighbors and the page as a whole. An audit returns evidence and recommendations without editing.

When feedback opens an unresolved visual choice or repeated revisions leave the user dissatisfied, use [references/taste-selection.md](taste-selection.md) to make a small playable lab before the next subjective iteration. Do not wait for more attempted fixes or substantial implementation; a numerical edit does not settle a remaining subjective choice. Other material unresolved taste decisions also use a viewable comparison by default. When the user wants to see a proposed treatment before it is applied, deliver a scoped, isolated demo before editing the actual page, even for a small tweak; a demo created afterward does not satisfy that sequence. The user can select or combine qualities without choosing an entire site's style. Delegated selection, an explicit request to skip comparisons, or exact routine repairs with no remaining visual choice may otherwise proceed without a comparison. Matching before/after captures still verify the implemented result.

For an interactive comparison of UI variants inside the project's real context, optionally use [references/prototype-variants.md](prototype-variants.md). It supplies preview isolation, stable variant links and safe switching; the taste-selection procedure still owns comparison scope and delivery.

For a new direction, make the product's idea felt through the interface. Typography, palette, imagery, space, surfaces and behavior should explain the same idea together. Find the relationship worth showing: what the visitor can collect, change, connect, compare, discover or accomplish. Let that relationship shape the composition and demonstration before selecting familiar page sections. Expression can serve understanding, curiosity and delight; it need not be justified only by task efficiency. Use [references/design-judgment.md](design-judgment.md) for this work, including concept exploration, assets and visual explanations. Sources and physical references are useful inputs, not an allowed-style menu or a requirement to imitate real objects.

Usability, accessibility, truthful content, and implementation constraints remain requirements, not aesthetic settings. Approval of a reference quality is not approval of its whole palette, layout, copy or interaction model. Before substantial implementation or delegation, distinguish approved qualities from material unresolved choices and explain the latter's purpose and tradeoff in a small reviewable proposal. Delegated selection or a request to skip comparisons permits one provisional direction; routine repairs inside an approved system need no new taste gate. Pass these distinctions to workers rather than converting an inference into a requirement. Later feedback updates the affected dimensions at the stated scope; promote a preference to this shared skill only when the user states it applies generally. Silence is not preference evidence.

## Choose priorities by surface

| Visitor's job | Design priority | Common wrong turn |
|---|---|---|
| Complete a task: tools, dashboards, forms, settings | Stable hierarchy, useful density, familiar controls, fast feedback | Turning routine work into an art-directed landing page |
| Understand: docs, articles, guides | Readable measure, wayfinding, examples, predictable rhythm | Huge display type and sales sections interrupting reading |
| Decide and act: marketing, pricing, campaigns | Clear offer, real evidence, visible action, subject-specific identity | Generic hero and feature tiles, or spectacle that hides the offer |
| Explore the work: portfolios, galleries, showcases | The work leads; navigation supports exploration | Decorative interface competing with the artifacts |

Choose per surface, not per industry: a developer tool's homepage and its settings screen have different jobs. Inside an established product, consistency helps people work. When the user requests distinct concepts, explore different ways to convey the idea across the whole experience, including its demonstration and motion. A shared component with palette changes is useful for comparing palettes; it does not establish distinct design directions. Share accessible primitives and state logic where useful, without letting that reuse silently dictate every concept's visible structure.
