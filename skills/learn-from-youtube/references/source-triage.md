# Triage a learning collection

Use before deep extraction when the learner supplies several videos, papers, articles, books or slide decks, or wants help deciding what to study. This is a learning-selection layer, not a new crawler, knowledge database or scheduled research service.

## Start from the learning decision

Establish what the learner wants to understand or do, current prerequisites, and relevant time constraints. Infer a reasonable starting point from the request; ask only for information that changes the selection. Separate discovery, understanding, practice and application instead of treating every goal as a summary request.

## Screen before studying everything

Create stable source IDs and record locator, type, author/date where available, accessibility, prerequisites, central contribution, overlap, apparent evidence quality and expected study effort. Mark assessment basis: metadata only, sampled, or fully reviewed. Missing access is unknown, not low quality; popularity is not credibility.

Choose useful roles rather than an opaque score: foundational explanation, worked example, primary evidence, application, alternative interpretation, or redundant/outdated material. Return a short study order with reasons and explicit defer/skip decisions. A source count is not an obligation to fully extract every item before making this triage recommendation.

## Join claims, not summaries

For selected sources, map concepts and claims to exact source locators. Preserve distinctive examples, assumptions, dates and disagreements. Repeated versions of one claim are not independent corroboration; deduplicate them without erasing provenance. Do not merge incompatible definitions, populations or conditions into an apparent consensus. Use authoritative research to resolve decision-changing disputes, or show what evidence would resolve them.

Build a learning sequence from prerequisites and the learner's goal, not necessarily upload order. Teach the shared model once, then add each source's unique contribution and competing account. A useful question should be answerable with inspectable source references; when evidence is missing, say so rather than filling it from an unstated model prior.

## Close the learning loop

Offer an explanation, retrieval question or small application task appropriate to the goal. Adjust the next step from observed answers and explicit learner feedback; do not infer mastery or emotional state from completion or silence. Keep subject evidence separate from observations about the learner. Correct misconceptions with an explanation and another opportunity to apply the distinction, not merely a score.

When an existing research/evidence system is available, inspect its real interfaces and pass source IDs, locators, claims, contradictions and selected learning goals into it. Do not invent APIs, duplicate its store, turn on collectors/schedules, or automatically publish to a personal knowledge base. Notes and learner state must remain portable rather than requiring a particular agent, app or model. Persistent personal learner records require the user's intended scope and destination.

## Delivery boundary

A triage result states what to study and why, what was actually inspected, and the next smallest useful learning step. A later full lesson follows the main output contract. Do not call metadata screening complete source coverage, or a collection interface a functioning adaptive-learning system without exercising it.
