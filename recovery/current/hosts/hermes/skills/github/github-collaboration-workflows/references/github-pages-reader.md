# Publishing an existing static reader on GitHub Pages

Use when Pages publication is selected or accepted by the user. Verify current GitHub documentation, account plan, repository visibility, permissions and Pages configuration before promising availability or access control. Repository visibility and website visibility are separate; private repository access alone does not protect a website. Confirm ambiguous exposure before publishing, and preserve repository visibility unless separately authorized.

Use the repository's existing Pages deployment mode where possible. Verify the supported API or workflow before enabling branch-based publication. A rejected plan/permission check does not authorize making repository history public or adding another service.

Link to the actual rendered HTML path, including a non-index filename. When within scope, read back README and repository homepage links. Preserve source-rights notices.

Bind deployment to the updated commit and inspect its current run; an earlier error or cancellation is not the final outcome. Fetch the public reader without authentication and require HTTP success. For an unchanged standalone artifact, compare served bytes with the committed file bytes, accounting explicitly for any selected build transformation. A green workflow alone does not prove the intended artifact is served. Read back Pages settings, repository and website visibility and the reader URL.
