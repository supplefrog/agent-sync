# Evidence and source portfolios

## Evidence grades

- **Source-confirmed:** official repository or documentation at a recorded version.
- **Exercised:** a real command, protocol, or workflow produced captured output.
- **Blocked:** the mechanism is documented but local execution is blocked by credentials, bootstrap, or host setup.
- **Unproven:** authoritative sources were searched without proof; say “not found/unproven,” not “unsupported.”

Record consequential checks as exact command, exit/result, scope, source path or URL, and the claim supported. A protocol handshake proves reachability, not a complete model task, recovery flow, or persistence guarantee.

## Intact-system pilot

1. Use a disposable project and isolated state directories.
2. Record repository URL, commit/tag, platform, and clean/dirty state.
3. Read official architecture and platform guidance before testing.
4. Run documented secret-free checks plus one native CLI, SDK, RPC, ACP, or JSONL smoke.
5. Exercise one persistence, reconnect, steering, child, or recovery boundary.
6. Shut down through the supported path and verify no worker remains.
7. Separate source-only claims, exercised claims, setup blockers, and unproven areas.

## Source-portfolio coverage

Use a native export or supported account API first. If a signed-in rendered list is required, capture rows in batches, continue through lazy loading until a repeated bottom load adds nothing, write batches to JSON/CSV, deduplicate programmatically, and verify total plus boundary items. Preserve canonical names, stable IDs, URLs, status, and delivery mechanisms. Do not alter subscriptions during inventory.

For YouTube, preserve channel IDs because RSS uses `https://www.youtube.com/feeds/videos.xml?channel_id=...`; handles alone are not durable feed keys. RSS solves upload discovery, not transcript acquisition, primary-source recovery, synthesis, retention, or application.
