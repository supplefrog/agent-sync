# Codex workspace relocation on Windows

Use only for moving existing local Codex workspaces and rebasing their persisted paths.

- Discover the executable through the installed PowerShell/CMD wrapper if the Store binary is ACL-blocked. Generate experimental app-server schemas from that accessible installed version; an older source checkout can lack project APIs that the installed runtime supports.
- Read `project/list` and inventory physical directories separately from thread records. Record an explicit source-to-destination allowlist, resolve collisions, and map only threads belonging to authorized moved projects before any mutation.
- Deduplicate reparse points, preserve dirty Git work and worktree relationships, and distinguish already-missing folders from failed moves. Prefer same-volume renames. Retain a compatibility junction only for a demonstrated unresolved dependency; remove it after the entrypoint's dependency checks pass, rather than leaving old-name shortcuts by default.
- Prefer installed `project/update` with existing IDs and explicit `roots: [{path: ...}]`; verify with `project/read`. Rebase the desktop's path-valued workspace hints and project trust table without modifying its unrelated settings or assignments.
- Treat `thread/settings/update` as loaded-thread-only until an installed-runtime probe proves otherwise. `thread/resume` can change effective permissions by reloading current configuration/trust. An update acknowledgement can precede durable settings application. Avoid loading dormant/helper/archived threads solely for a path edit.
- If a closed-app offline migration is necessary, take SQLite online backups and exact rollout backups first. Change only structured execution-path metadata, never messages or embedded historical prose. Paginated history stores JSONL byte offsets: any changed record lengths require exact offset rebasing from line boundaries in `thread_turns` and `thread_history_projection_state`. Do not assume that changing `threads.cwd` alone updates resume history.
- Verify every original thread field except explicitly mapped paths, every conversation record byte-for-byte, every projected history row with only expected offset changes, database integrity/foreign keys, archive status, Git HEAD/status, and directory identity/file counts. Read every migrated thread through the native API and exercise real paginated history reads. Keep rollback evidence private; do not restore whole old databases over later conversation activity.
- Require replacement evidence and unique-work/dependency review before supersession deletion. Empty folders, helper status, age, repeated names, and completed tasks do not alone establish deletion safety.
