# Model-Triggered Instruction Retirement

Use after a materially changed inference stack is selected for an active route, or when evidence suggests persistent instructions are causing negative steering. A release announcement without active-route selection does not reopen the library.

## Classify units

- **Generic steering:** style, scope habits, generic planning/review rituals, broad aesthetic heuristics. Model-sensitive and eligible for release-triggered ablation.
- **Task procedure:** commands, APIs, scripts, templates, local traps, and deterministic verification. Reopen on owner/tool/environment change, not model name alone.
- **Safety/governance:** permissions, privacy, destructive-action, provenance, promotion, and rollback guarantees. Deduplicate wording only when an equivalent enforced owner remains; never remove the outcome from a bare-model result alone.
- **Environment fact:** move to config, project documentation, or memory when that is the real owner.

## Materialize the effective unit

Retirement plans must target what the selected host actually injects:

- Filter out units whose host set does not include the target host.
- Treat canonical/reference source text as ownership input, not as a live behavior-ablation arm. Materialize the rendered effective host artifact unless equivalence between source and live injection is explicitly proven.
- Prefer an effective host unit over an identical reference unit so declaration order cannot make the reference shadow the live owner.
- Split mixed blocks before evaluation. Generic steering, workflow routing, deterministic procedure, and protected guarantees must have independent selectors; never remove a whole paragraph or section because only one sentence is model-sensitive. A selector-only split may preserve prompt bytes while making later evidence attributable.

Run the exact-transport credential/route preflight from `cross-host-eval-transport.md` before any repeated model calls. A failed preflight is an inconclusive harness result and permits no retirement.

## Bounded cascade
1. **Static pass:** remove exact duplicates, dead references, superseded aliases, unreachable triggers, and copied host text with one shared owner. No model calls.
2. **Prioritize:** queue only large, always-on, overlapping, repeatedly corrected, or model-sensitive units. Telemetry ranks candidates; non-use is not deletion proof.
3. **Bare gate:** run a compact owning suite on the exact new stack without the candidate instruction.
4. **Full gate:** compare the complete current owner with bare. If full has no meaningful win, prefer no instruction for new admission and mark existing generic steering for retirement testing.
5. **Leave one out:** compare full with full-minus-unit on owning cases plus a small cross-surface canary set.
6. **Minimize only when needed:** if full beats bare but units overlap, use binary splitting or delta debugging. Do not evaluate every combination.
7. **Measure nondeterminism deliberately:** for subjective or variable behavior, publish the trial/seed count and variance/confidence rule before seeing results. Repeat independent paired trials when one result could change the decision; a single win or tie is not sufficient evidence for a broad mutation.
8. **Escalate only at the boundary:** use deterministic artifact checks first, then one blind paired judge per trial for unresolved subjective cases; expand sampling only for ties, high variance, or high-risk decisions.
9. **Cache exact evidence:** key by model, provider/transport, reasoning effort, tool policy, prompt assembly, unit hash, suite hash, harness hash, seed, and trial count.

## Trigger and cross-host cache boundary

A release or catalog signal is only a research wake-up. Reopen instruction retirement when the effective active route stack changes, including a pinned model/provider snapshot, alias movement, reasoning or tool-policy change, prompt/context assembly change, or relevant runtime change. Persist a canonical active-stack fingerprint so a changed active route is not missed and a merely listed candidate does not reopen the library by itself.

Treat a cache hit as proof of effective-stack equivalence, not merely equal model names. Include or explicitly prove equivalence for host, provider transport, model snapshot, reasoning/decoding, prompt/context assembly, tool policy/schema, runtime, seed, and trial count. Default receipts to host scope; reuse one portable winner across hosts only after equivalent-stack proof and required-host behavior gates pass.

A clean tie favors deletion for generic steering. Retire only when full-minus-unit has no critical loss, no meaningful aggregate regression, no unique procedure/environment knowledge/protected guarantee, and rollback exists. Noisy evidence is `inconclusive`, not permanent retention.

## Grader discipline

Deterministic graders should test true invariants: artifact existence, schema validity, required tool effects, forbidden side effects, or exact formats explicitly required by the task. Do not require incidental words in prose; a correct model can paraphrase them, creating false hard failures. Use case-scoped criteria and blind comparison for semantic quality.

## Automation boundary

A release monitor may produce a bounded plan and evidence after an active-route recommendation. It must not mutate live prompts, skills, routing, or pinned work and must not invoke a whole-library LLM curator. Promotion or deletion remains a separately reviewed, reversible batch followed by fresh discovery and representative smoke tests.
