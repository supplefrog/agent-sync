# Portable capability convergence

Use only after a winning substrate/authority has been selected, when reducing capability drift across multiple agent hosts. If the task is choosing between complete harnesses or replacing the incumbent authority, first use `whole-system-substrate-evaluation.md`; do not predeclare a portable-core/thin-adapter architecture that prevents a whole-system candidate from winning. Reopen earlier convergence decisions when their owner choice depended on an authority or interaction invariant that has changed.

## Target architecture

- **Portable core:** one deep owner for host-independent procedure, contracts, evaluation, and evidence.
- **Thin adapters:** only host discovery, configuration, invocation, packaging, and verification differences.
- **Irreducible native strengths:** capabilities whose semantics cannot be faithfully replicated; record them as routing signals rather than forcing symmetry.

Equivalent verified outcomes matter more than identical file trees or installed-skill counts.

## Curator roles

Do not conflate curators that share a name:

- A host lifecycle curator manages that host's skill usage, staleness, archival, and overlap consolidation.
- A cross-surface curator decides ownership and precedence across instructions, skills, hooks, config, plugins, and hosts.
- A delta minimizer implements admitted missing outcomes after ownership is decided.

Run a host lifecycle curator only against its own managed library. Make the cross-surface curator reachable from every host through one portable procedure plus minimal native wrappers; never fork the deep decision procedure per host.

## Convergence loop

1. Inventory actual fresh-session capability, not directories or standalone resource commands that initialize no session catalog.
2. Classify each capability as portable core, adapter, or irreducible native.
3. Choose one coherent owner. Preserve a working lower-precedence/shared owner instead of adding a higher-precedence copy; never union every host's instructions merely to retain overlap.
4. Use the cross-surface curator for ambiguous ownership, overlap, or precedence.
5. Validate the instruction/capability evaluation gate before broad mutation. Admit and port only a live-session-proven gap whose candidate beats the baseline without required-host regression.
6. Normalize controllable inference-stack variables before costly cross-host behavior trials; sample nondeterministic outcomes according to the owning admission/retirement contract.
7. Remove or disable inferior/conflicting duplicates only after provenance, rollback, and fresh-session verification. Keep irreducible native variants explicit rather than flattening them.
8. Verify fresh-session reachability in every changed host and record rollback.
9. Maintain a machine-readable overlap/delta map plus human-readable setup and routing guidance.

## Disconfirming checks

- Does each native adapter still point to the same portable owner?
- Does a fresh host session resolve and trigger it?
- Has an adapter accumulated portable logic or unrelated host quirks?
- Is a claimed gap actually an irreducible native semantic difference?
- Can a clean clone reconstruct portable behavior without copying secrets, state databases, sessions, caches, or generated installation output?
