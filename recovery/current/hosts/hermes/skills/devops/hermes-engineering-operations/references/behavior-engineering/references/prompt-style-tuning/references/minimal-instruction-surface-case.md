# Minimal-Instruction Surface Case

## Failure pattern

A concise provider setting did not prevent redundant answers because two prompt surfaces independently required mechanisms, causal models, and tradeoffs. When the user made a decision, the agent treated it as an invitation to restate the decision, add bullets, and propose a “refinement.” Another prompt phrase—“let the agent determine the method”—merely described competent default behavior.

## Audit pattern

1. Inspect `SOUL.md`, `agent.system_prompt`, active personality, provider-native verbosity, and injected preference memory together.
2. Mark duplicate owners, universal elaboration rules, default-autonomy instructions, and requirements the model can infer.
3. Keep broad communication behavior in one surface. Delete redundant overlays rather than adding another concision rule.
4. Preserve operational execution guidance unless the observed failure implicates it.
5. Replay the exact corrected exchanges in fresh sessions. Include a preference statement, a user decision, and a direct correction.
6. Grade whether the agent applies the instruction without summarizing or improving it. Clean up temporary evaluation sessions.

## Effective distinction

- Novel task prompt: irreducible intent, non-obvious constraints, success criteria.
- Repetitive task prompt: established procedure, required format, verification checks.

Do not add “choose the method,” “exercise judgment,” or equivalent permissions.

## Observed evaluation lesson

A first simplification still produced a bulleted restatement. The effective rule was narrower: default to the shortest complete answer; apply stated preferences and decisions without summarizing or refining them unless materially wrong or unsafe. This reduced the representative decision response to a direct acknowledgment while retaining deeper responses for tasks that requested analysis.
