# Never-active pruning authority probe

Use this focused probe when a maintenance cleanup can cascade-delete a session tree.

## Contract

A stale, never-active keyed session is removable only when no durable ownership receipt names it as either the owned parent or owned child. An owned parent must not be selected: the destructive path may cascade-delete its delegate child. An owned child must also be protected unless its explicit integration/cleanup authority has been consumed. Unowned stale rows must remain eligible so the fix does not disable legitimate cleanup.

## Review steps

1. Trace `list_*`/candidate SQL into the actual prune/delete caller. Confirm the ownership predicate is present on the selector that supplies IDs to deletion, not only on a dry-run or preview API.
2. Build a real temporary `SessionDB` with an old keyed parent, a correctly attributed subagent child, and an ownership receipt. Invoke the public maintenance prune entry point. Assert `(deleted, routing_deleted) == (0, 0)` and both session rows still exist.
3. In the same test family, create old unowned keyed rows plus young/used/ended rows. Assert old unowned rows are removed and protected rows remain; verify routing entries for removed rows are cleaned up.
4. Run the focused regression file and the nearby ownership/state suite. Use `PYTHONDONTWRITEBYTECODE=1` when the repository must stay free of generated bytecode.

## Evidence pattern

Report the selector predicate, the production destructive caller, the owned-parent/child retention result, the unowned-candidate deletion result, and the exact test counts. Do not infer safety from a list result alone when deletion can race or cascade.
