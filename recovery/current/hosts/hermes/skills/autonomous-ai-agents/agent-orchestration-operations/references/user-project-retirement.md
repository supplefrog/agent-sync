# User project and conversation retirement

For explicitly authorized retirement of user projects and conversations, distinguish that authority from automatic ephemeral-worker collection. Treat the user's current completion statement as authoritative over old summaries or a missing end timestamp; separately check live activity and unique material. Infer other stale candidates from outcomes, supersession and upstream evidence instead of requiring the user to label every thread. First move still-relevant work and integrate missing requirements, decisions, code and acceptance artifacts into the proper durable owner. If upstreaming is authorized, verify remote coverage before removal; an export or matching old remote ref is not proof. Then perform the scoped dry-run and approved removal through normal gates, preserving unresolved unique material. When the requested outcome includes disk reclamation, cover verified stale project files and in-scope archives as well as library entries; do not substitute archival or replacement backups for removal. Read back exact target absence and report measured storage reclamation separately from logical thread counts.
