# Hermes local-change lifecycle

Hermes owns this native updater source. Agent Sync retains an exact, hash-bound recovery patch and the MIT license. This package adds no shared skill, host parity, configuration recovery, or live deployment claim.

With the explicit `updates.parked_branch_strategy: update_in_place` strategy, the checkout advances to the exact upstream HEAD. The updater saves original committed history (H), staged index (I), unstaged working tree (W), and untracked files (U) through durable `refs/hermes/source-snapshots/<id>/head` and `/stash` refs. Previous stashes remain untouched. Compatible formerly committed changes become staged; staged and unstaged distinctions are retained above that layer. Preservation applies to general local source changes without registration.

Related paths from local commits and uncommitted layers form coherent groups. Conflicting or uncertain groups remain saved and inactive while the upstream update proceeds. Unsupported changed file types and invalid Python syntax also require review. The updater engine forms one group: if it conflicts, the next invocation uses the upstream updater until the extension is recovered. `--keep-stash` keeps local changes inactive. Only explicit registration with a restricted pure-function behavioral oracle can prove an upstream fix supersedes a registered patch and authorize retirement. That narrower retirement mechanism supports one active registration per worktree; saved originals remain retained after retirement.

An atomic JSON journal and recovery instructions under the Git directory's `hermes-update-patches/.../source-snapshots/` record phase, target, active/inactive groups, and saved identities. Native interrupted-pull recovery repairs interrupted source writes. Exact completed installations may settle; uncertain interrupted state preserves current edits and saved originals without automatic replay. For manual recovery, use a separate checkout: `git worktree add --detach <new-empty-directory> <snapshot-ref>/head`, then `git -C <new-empty-directory> stash apply --index <snapshot-ref>/stash` if a stash exists. Review identities before deleting any saved ref or stash.

Unfinished Git operations, unmerged index entries, hidden index flags, sparse checkout, intent-to-add entries, an unverifiable Git environment, and pending native recovery require resolution before source mutation. Branch switching and release-channel updates follow their separate native behavior. This package does not select configuration or recreate an installation.

For package recovery, prepare a disposable checkout at the exact upstream `base_revision` in `manifest.json`. Verify every `before_sha256`; null requires absence. Run `git -c core.autocrlf=false -c core.whitespace=cr-at-eol apply --check repair.patch`, apply with the same options, and verify every `after_sha256`. Stop on mismatch and preserve unrelated work separately. Reverse application is appropriate only when current files still match all after hashes and no later work would be removed.

The manifest contains the final frozen test evidence and its source binding. Package construction checks exact upstream preimages, patch application, and every resulting source hash in a disposable Git fixture. Runtime activation and service boundaries mocked by the tests are explicitly recorded in verification; those checks do not establish a full live service restart. No model or provider calls are used. This record contains no provider settings, credentials, sessions, memories, logs, or unrelated native repairs. Publication and live deployment require their own receipts.
