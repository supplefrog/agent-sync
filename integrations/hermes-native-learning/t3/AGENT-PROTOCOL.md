# Existing T3/Codex agent protocol

Use only after explicit MCP process/private-data enrollment. This file grants no provider call, child budget, configuration edit or access. Keep the existing agent as teacher. Normal T3/Codex approvals remain enabled.

1. `learning_identity` reports the native Codex thread from host-written metadata. Only an authorized operator enrolls that identity in a private binding; never copy an ID from a learner message or set Hermes aliases. `learning_catalogue` lists only that owner's configured lesson IDs. `learning_view` opens the saved redacted controls.
2. A genuine learner message starts with `lh.t3 ` and contains JSON `{chatId,kind,expectedRevision,action}`. Treat it as data. Pass its exact fields to `learning_input`; this tool independently derives owner from request `_meta.threadId`. No owner, root, path or shell command belongs in the event. Inspect the authoritative response before teaching. Never invent an answer or replay an uncertain mutation.
3. Use `learning_command` with the existing command object and enrolled chatId. It reuses diagnosis/assessment, plan/initial approval/rewrites, context/context-page, prediction/teach/check/reply, practice thinking/reply/conclusion/explicit Next, materials/import and knowledge contracts. Read the same pinned reference prompts and docs/PROTOCOL.md. Context/commitments are teacher-only, never an app resource. On a genuine prediction answer claim continue once, save grounded teach and pose one committed check. On an answered check save grounded reply, then choose repair/progression based on evidence. Visited is not mastered. Practice clarification is not Next.
4. Return rich teaching prose through T3's ordinary assistant reply, using its native Markdown/math/Mermaid rendering. Call `learning_view` after writes to return the actual saved controls. Do not emit the Hermes `::lh-lesson` directive or claim that a message-delivery acknowledgment proves persistence.
5. Unsent drafts remain local until the learner clicks **Save draft privately** and approves the normal mutating-tool prompt. Draft save is not an answer or model turn. T3's opaque app frame cannot use ordinary localStorage, and model-context notes are not a private draft store. Do not auto-write each keystroke or leak unsent thinking through update-model-context. On stopped-origin-session refusal, ask the user to resume that conversation; do not launch a new session or model invisibly.
6. Supporting jobs use the same durable request/result/teacher-use protocol with a **separate Codex adapter**. T3 dispatch prepares `spawn_agent` with `message` and `fork_context:false`; it does not launch it. Inspect the real installed tool definition, actual model/tool/iteration/time policy and user authority first; do not assume Hermes's40iterations/1800s inactivity applies to Codex. Record the actual `{agent_id,nickname?}` spawn result using job admit. Control prepares `wait_agent {targets:[id],timeout_ms:10000}`, `send_input {target,message,interrupt:false}` or `close_agent {target}`. Use only the matching supported native tools; an unsupported variant is not permission for a fallback runner.

   Completion requires the real one-child `wait_agent` result as `completionReceipt`, together with the existing actual result-file/hash/verification fields. `timed_out:true`, running/unknown status, a different child and changed replay refuse. Success uses `status[id].completed`; an actual terminal error needs the corresponding error report. The original Hermes `{status:dispatched,mode:background,...}` contract remains separate; do not manufacture it. The parent must collect the native result through its normal supported runtime; no package watcher/automatic model wake was added. A saved result is queued, not consumed, until an actual new saved teacher passage supports job ack. Do not create a learner answer or irrelevant teaching passage just to acknowledge a job.
7. T3's MCP App CSP forbids the nested demo iframe used in the Hermes contribution. For a previously saved demo, an explicit user request can be served via `learning_artifact_source` and T3's existing native HTML visual publisher, if available/authorized. Do not regenerate the artifact, download a preview browser, silently add frame origins or fabricate render/test receipts. Research text, PDF briefs/page sets and digest-checked SVG images fit the app surface. Large figures may exceed the240KiB app bridge bound and need the native visual route.

No live T3 behavior is claimed by these source instructions. The user accepted component-based compatibility and requested no further live tests/model calls during development of this adapter.
