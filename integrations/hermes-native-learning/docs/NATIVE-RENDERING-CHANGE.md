# Native rendering change

The requested outcome is saved rich visuals available through the existing MCP and usable lesson controls in native Codex desktop. The chosen implementation reuses the existing state machine and inline controls. No second teaching runtime, browser-to-database endpoint or background worker is added.

Teacher visuals are immutable, bounded source records with public content-addressed descriptors and explicit reveal timing. Native Codex receives a generated fragment with a revision-bound, user-confirmed message transport. T3 keeps its App and native demo publisher; Hermes keeps its existing artifact sandbox. A general MCP Apps replacement was deferred because native Codex UI support for that interface was not established by the inspected contract.

The installed release contained existing shared-workspace, current-projection/reopen, probe-completion and recovery fixes absent from the published source snapshot. Those source fixes were preserved when preparing the successor, rather than deploying an older state/UI implementation. Private startup instrumentation was excluded. The current-index test fixture now supplies index and snapshot separately, matching the installed reader contract; cancellation checks remain intact.

Verification includes the existing backend/DOM suite plus native-visual tests. The focused native tests first failed because the visual command was absent. They now drive command persistence, own/foreign metadata, deferred reveal, changed asset bytes, exported controls, exact response content/revision, repeated-click suppression and replay rejection. Review found and corrected attachment of deferred visuals to a concluded practice problem and source sizes exceeding the T3 JSON bridge. Both have regression cases. A prior genuine user interaction in native Codex demonstrated confirmed input, MCP persistence, teacher feedback and read-only reopen; offline tests do not replace that observation or qualify every host variant.

The pinned T3 dependency audit reports eight low-severity dependency entries rooted in an inherited KaTeX trust/prototype-pollution advisory. No moderate/high/critical entries were reported. Renderer pins and security policy were preserved; dependency upgrades require their own compatible renderer/notice review. Native Codex lesson fragments do not bundle that math dependency tree.

Publication, installed release identity, fresh-process loading and observed UI behavior are separate states. The task's delivery receipt records them. Switching the configured package does not change code already loaded in an active MCP process. Reload through the host's normal lifecycle; preserve private bindings, state and recovery copies.

Rollback selects the preceding MCP package path and retains state. This change adds optional visual records; it does not migrate or delete learning history. Older readers ignore optional visual metadata but cannot render it. Keep this record linked from the package README and retain deployment evidence outside shared source.

## Responsive layout and MCP App startup

The Codex renderer uses the same question controls with a two-column layout when an attached visual and the response both fit. On narrow surfaces the visual sits immediately above the question. Saved practice feedback stays readable and can be collapsed. T3 continues to use its original layout.

The previous App accepted only the T3 host name, so it did not acknowledge initialization from Codex desktop. The App now recognizes the Codex desktop identity sent by the installed host. It uses the existing owner-scoped refresh and user-confirmed message routes. SVG can render beside the response; interactive HTML opens in the chat renderer. A browser fixture exercises the actual App bundle and state boundary using the observed host identity. It does not replace a live Codex mount check.

A visual correction uses a new immutable ID and supersedes the previous asset in current projections. A correction keeps a pending reveal protected. Prior records remain available for recovery. App drafts are reconciled only when the current lesson shows a new saved entry with the exact submitted text. Typing after delivery retains the newer draft.
