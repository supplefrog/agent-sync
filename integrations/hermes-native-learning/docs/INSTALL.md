# Opt-in installation and removal

These are proposed activation steps, not a record of installation. Do not copy the plugin into a watched root before approval: the loader can evaluate module code even when `defaultEnabled` is false.

1. Finish source/bundle review and record hashes. Wait until the target app is idle and unsaved work is preserved. Do not restart, reload an active conversation, change the main model, enable tools globally or modify credentials.
2. With explicit trust approval for these pinned bytes, place only the built ESM at `$HERMES_HOME/desktop-plugins/learnharness-native/plugin.js`, then enable LearnHarness Native through normal Hermes controls. No installed Hermes source patch is needed. If the supported plugin UI/loader is absent, stop; do not substitute a private bridge.
3. Copy `bindings.example.json` to a private workspace as `bindings.local.json`. Set a chosen lesson ID, teach/practice mode, disjoint workspace-relative state/export directories and the **verified owning Hermes conversation ID**. No model-provided path or owner fallback is accepted. Do not publish this file. Existing lesson migration requires a verified backup and explicit mapping; `init` creates only a new missing record and refuses overwrite.
4. In the first admitted read-only qualification turn, correlate this conversation's trusted transcript ID with the command's Hermes per-command `HERMES_SESSION_ID` / `HERMES_UI_SESSION_ID` aliases using non-content receipts. Successful correlation is an outcome of that bounded turn, not a prerequisite requiring another unallocated turn. The environment contract is not authentication. Never set an alias from a message, use the active session as fallback, or export global aliases to make a check pass. If correlation fails, stop before writes or accepting an answer.
5. Use a fixed CLI executable/config path through the existing agent's terminal tool. Pass command JSON by stdin, not shell interpolation. The CLI accepts only a configured lesson belonging to that qualified caller. The optional skill is task-scoped; installing it globally is not required or implied.
6. The agent returns the exact `::lh-lesson{lesson="..." snapshot="..."}` from the command result. The SDK resolves the owning transcript session. In that card, explicitly select only its generated export directory with **Connect lesson exports**. This folder grant and plugin storage binding survive reopening. Do not select raw state, profile/history, credential or unrelated work directories. Streaming cards cannot request a folder.
7. The first qualification turn returns the read-only saved question/card. Within a two-input-turn acceptance scope, the second input is the learner's real answer: do not insert an extra Resume submission between them. Reopening without submission requires no new turn; testing another Resume delivery needs an allocation covering that input. An input click delivers `lh.native` JSON to `host.composer.submit(ownerSessionId,text)`. The existing agent runs the fixed handler, inspects its result, and returns the new directive. This is a real agent turn, not a zero-model callback. Approvals/costs remain normal host policy. Missing route, rejection or stale revision retains the unsent draft; do not automatically resend.

To disable, use Hermes's normal plugin control while idle. Revoke the export-folder grant through supported app controls if available. Remove the pinned plugin directory only after preserving its source/manifest and any desired rollback. Do not delete lesson records, draft storage, LCM data, credentials or history. Enabling/disabling this integration does not alter global memory, compaction or tool settings.

The implementation reads snapshots through picker-granted IDs and stores owner/lesson/folder mappings and drafts in plugin storage. It has full trusted-plugin authority on load; this is an implementation restriction, not a guarantee that the SDK is a security sandbox.

Graph-tagged practice is optional and off when graphRoot is omitted. Enabling it requires a separately chosen existing native graph directory and explicit read authority for its format.json/nodes.jsonl plus disclosure of proposition names/statements to the owning teacher. Do not guess another profile when the configured source is absent. No source was enrolled by this package preparation. A basic lesson activation need not grant graph access. The example binding intentionally contains no graphRoot.

Optional materials, writable knowledge/job roots and supporting child model/tool calls require their own exact enrollment and data/provider authority; they are omitted from the basic example. See [materials/jobs](MATERIALS-JOBS.md). None were activated during source preparation.
