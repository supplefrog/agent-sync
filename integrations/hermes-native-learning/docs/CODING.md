# Coding questions

The existing lesson owns the coding question or problem. The learner edits the full response, can run the tutor's examples, and submits code in the ordinary teaching or practice flow. The lesson keeps exact code and any separate learner thinking. The test result describes the supplied examples and can inform the teacher's assessment.

## Authoring a question

A coding question is a teaching text response (`explain`) or a practice `problem` with this additional commitment:

```json
{
  "coding": {
    "language": "javascript",
    "starterCode": "function square(n) {\n  // Your code here\n}\n",
    "tests": [
      {"name": "Squares a positive number", "expression": "square(3)", "expected": 9},
      {"name": "Squares a negative number", "expression": "square(-2)", "expected": 4}
    ],
    "solution": "function square(n) { return n * n; }"
  }
}
```

Keep the original teaching correct-answer or practice model-solution fields consistent with `coding.solution`. The pending view exposes the starter code and test names. The test expressions and expected values live in the private commitment. The solution is shown at the normal answer or practice-conclusion reveal.

The learner explicitly chooses **Run tests**. The host resolves the identity of the enrolled lesson, its current revision, and its current question or problem. Each example sees a fresh QuickJS context with the submitted source. It evaluates the expression, serializes the synchronous result to JSON, and compares with the committed expected JSON value. Exceptions, timeouts, and different return values appear as distinct observations. A matching server receipt may accompany the learner's eventual submission. Editing the source or changing lesson revision invalidates the receipt. Running tests keeps the question pending.

The runner supports pure JavaScript exercises. It has no installed-module, filesystem, network, CLI, or asynchronous I/O support. Use test expressions that return synchronous JSON values. A solution is required. A starter and tests are optional.

## Runtime and corresponding source

The isolated runner uses the QuickJS WebAssembly variant built without filesystem support. Tutor and learner code run in the same restricted guest language, with no host APIs registered. Node's worker boundary carries input and per-test observations, has a separate wall-clock deadline, and is terminated after a result. Guest code has per-test CPU, stack, and memory limits. The worker never receives the committed model solution.

The runtime bundle is generated by `build-coding-runtime.mjs`. Use the existing esbuild 0.28.2 toolchain and preinstalled npm package tarballs, with package scripts disabled. The build neither downloads dependencies nor reads learning data.
