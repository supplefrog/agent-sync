# Fixed local command protocol

Invocation: `node <reviewed-package>/src/cli.mjs <private-workspace>/bindings.local.json`, with exactly one JSON command on stdin. Quote fixed paths using the host shell's structured/file-input facilities; do not interpolate learner bytes into command text. Input limit64KiB, raw record limit4MiB, teacher context limit256KiB; oversize data fails, never silently truncates. Paths come only from the private configuration.

For long saved lessons, `context-page` returns exact teacher context in bounded pages instead of inventing a summary or losing the active commitment. Default is the latest30messages; `limit` accepts1–100. Explicit `offset` requires the captured `expectedRevision`, and stale navigation refuses. Page metadata gives total, previous/next offsets and authoritative revision; current assessment/plan/continuation and the pending tool commitment remain available even when the question lies outside the selected history page. Assistant private-thinking blocks and provider metadata are excluded. This is teacher-only context, never a learner-facing directive. Oversize pages refuse; request fewer messages. No model, compaction run or automatic wake is launched.

A state mutation can succeed while the subsequent export fails. Such a response explicitly reports `operationComplete`, `persisted`, `authoritativeRevision` and `presentation.available:false`, with no directive. Do not repeat a saved tool call to repair its presentation: reopen current state/context, preserve the returned revision and resolve the export issue separately. Successful native exports stay within the reader's256KiB boundary.

All lesson-specific commands have `chatId`; owner-scoped `list` accepts only `op`. `init` accepts `title,goal` and creates a missing configured record only. `view`/`export` read the current view; `context` returns teacher-only content. Tool mutations use `op:"tool", expectedRevision, authorship:"host-agent", toolCallId, name, input`. Teaching names: ask, probe, recall, probe_done, plan_init, quiz, explain. Practice names: problem, conclude. Schemas/validations are the reused contracts; see backend controls for synthetic examples. IDs must remain stable across delivery/reopen.

`lh.native ` is followed by `{v:1,ownerSessionId,chatId,kind,expectedRevision,action}`. The CLI independently resolves its configured owner from the qualified per-command caller. Teach actions: `answer` with stable `toolCallId` and `request`; `approve` with `planRevision,text`; read-only `resume`. Practice actions: `practice-input` with upstream `thinking` or explicit `next`; read-only `resume`. Never accept an alternate root, owner fallback or unknown fields.

Teaching `continue` claims the current owed reaction idempotently. `teach` uses `expectedRevision,authorship,continuationId,nodeId,predictionCallId,text`. `reply` uses `expectedRevision,authorship,continuationId,afterToolCallId,text` for check feedback. `question` uses the same revision/authorship plus `toolCallId,name,input`. Practice `practice-reply` uses `expectedRevision,authorship,problemCallId,afterThinkingId,text`; it must follow the latest unreplied thinking entry for the active problem. Repeated feedback cannot consume the same thinking twice.

The success result includes a fresh immutable snapshot and exact directive. Snapshot basename contains kind, revision and full SHA256 of the projected JSON. The frontend checks those bytes and owner/lesson/mode; commitments are omitted until the appropriate reveal. Raw state has the teacher commitment. Exports may include previous learner answers and thinking and must remain private. Historical content under a digest basename cannot be overwritten.

`context` additionally returns read-only `workflow` facts: current stage, allowed reaction shapes and stable input/claim identity where applicable. These are guidance over the existing record, not automatic grading or a new runtime. Practice pause input accepts upstream `{type:"text",text}` only after conclusion and before Next. `practice-discuss` takes `expectedRevision,authorship,afterMessageId,text`, must answer the latest unreplied pause message, and cannot advance or re-pose a problem. Explicit Next remains separate.

The native contribution uses the SDK's MessageTextContent for teacher prose, problem statements, hints, revealed solutions and a generated plan DAG. Math and Mermaid come from the host pipeline, not installed renderer dependencies. Rich check text respects the existing open/close state; learner drafts/controls remain in the reused UI. Text that contains link/image/media/raw-HTML syntax uses a literal fallback. Fence languages use a conservative allowlist for the inspected host: Mermaid and ordinary code formats remain rich; unsupported active fences such as listing/SVG fall back literally, including mixed-case and tilde syntax. Paragraph decoration prevents recursive live transcript directives. Choice labels and learner working traces, including concluded practice thinking, remain plain text. This source support is not proof of actual pixels or host rendering success.

Optional tagged practice requires explicit private `graphRoot` enrollment, pointing to an existing native LearnHarness graph directory. Only `format.json` and `nodes.jsonl` are read, never modified. Root may be external only when explicitly configured with the additional data-read authority; it must be disjoint from mutable state/exports. File links escaping the enrolled root fail. Format1 (or absent legacy stamp) is accepted; malformed assertions/newer formats fail, with a4MiB per-file limit and no silent truncation. The first identity for repeated IDs is retained, matching the existing reader. No referenced notes, chats, chains or credentials are opened.

Teacher context contains the source hash and proposition IDs/names/statements. A nonempty problem target is normalized using the pinned upstream resolveTargetId body and checked against a fresh whole catalogue at pose time. Unknown/deleted IDs fail without a lesson write; plan nodes are not propositions. Untagged topic practice still works without any graph enrollment. Graph presence is not mastery. Validation is implemented; extraction/merging and real graph-source enrollment remain separate.

Native submission is through the SDK's explicit owning-session composer method. Plugin storage keeps drafts with owner/lesson/question identities. A successful delivery waits for the agent's new authoritative card; it does not fabricate persistence, feedback or a model turn. No background polling, HTTP endpoint, provider API client or automatic retry is part of this protocol.
# Enrolled lesson lifecycle and knowledge commands

`{"op":"list"}` lists only lessons explicitly configured for one qualified owning conversation. It accepts no caller-supplied owner/path or history. A missing/ambiguous owner refuses. No profile scan, conversation creation or new folder grant occurs. A configured missing lesson can be created through existing `init`; an existing lesson reopens through `view`/`export`, preserving question identity, drafts and teaching state.

`rename` accepts `chatId`, `expectedRevision`, declared `authorship` and `title`. It preserves transcript and activity time, increments the authoritative revision on a real title change, and refuses stale writes. Return its fresh card rather than keep submitting an older revision. Rename is not lesson progress or a new teaching turn by itself.

Optional post-hoc proposition extraction, identity audit, atomic graph merge and graph-linked practice use the same CLI lane. See [knowledge commands](KNOWLEDGE.md). They require explicit private knowledge-root enrollment; never infer a source directory, create a provider client, or use model-provided paths.

Optional [material/import/job commands](MATERIALS-JOBS.md) return their own data acknowledgements. After a successful data mutation, use read-only `export` for a fresh card; do not repeat the mutation to obtain a directive. A queued worker result is not teacher consumption, and an error report is not a learner answer. Only actual new teacher prose can acknowledge either. Snapshot and asset digests change when supporting work changes even if the pending lesson revision is unchanged.
