# LearnHarness native host adapters

The Hermes contribution below is retained. A source-only T3/Codex MCP App adapter now reuses the same learning state/contracts and inline controls; see [T3 integration](docs/T3-INTEGRATION.md). It authenticates host-written MCP thread metadata rather than manufacturing Hermes caller aliases. The two hosts use their own supported UI/input/worker interfaces. No T3 application fork, provider client or teaching runtime was added. T3 live activation/evaluation was deliberately not run; the user accepted component-based compatibility and requested no additional live tests/model calls.

An opt-in integration candidate for learning in an existing Hermes Desktop conversation. The existing agent writes assessments, plans, questions, explanations and practice feedback. This package provides durable tool/input contracts and inline controls; it contains no model client, background teacher, server or automatic agent wake.

Status: source candidate, not persistently activated or published. The reviewed Hermes bundle completed one genuine native answer→owning-teacher feedback→saved check→reopen interaction on a private copied lesson; temporary plugin/folder access was removed afterward. Supporting-job dispatch/result and the other live feature variants were not qualified in that short flow. The new T3 adapter and Codex worker-receipt branch require source review; no live T3/model/child test is claimed. Earlier source controls use synthetic data and overlapping receipts, not a full product percentage. See [product map](docs/FEATURE-MAP.md), [qualification](docs/QUALIFICATION.md), [installation](docs/INSTALL.md), [agent protocol](skills/hermes-native-learning/SKILL.md) and [provenance](NOTICE.md).

Implemented contracts include diagnostic assessment, editable DAG plans with initial learner approval, committed prediction/check answers, stable question IDs, reasoning and confidence, explicit host reaction claims, feedback, one pending question, stale/replay rejection, immutable view snapshots and reopen. Practice supports a committed hidden solution, learner thinking, agent hints/feedback, conclusion reveal and explicit Next. SDK drafts are scoped to owner, lesson and question; concurrent windows have no atomic compare-and-swap guarantee.

The selected inline UI is reused. A read-only workflow projection and pinned upstream doctrine guide the actual host through diagnosis, planning, prediction/teaching/check, repair and practice. Practice retains between-problem questions and replies without interpreting clarification as Next. Optional knowledge commands now implement teacher-prose coverage, extractor findings, source-free identity-audit projections, atomic upstream graph merging, source-linked proposition review and fresh graph-tagged practice. They launch no models; source-blind model auditing and automatic background dispatch remain distinct host obligations. Existing enrolled native graph readers remain available. Owner-scoped listing/create/resume/rename uses explicit configuration rather than a profile scanner. The native contribution uses Hermes's public Markdown/math/Mermaid renderer for lesson prose, preserving reveal gates and plain fallback for link/image/HTML content. Choices also have a rich presentation using their original shuffled indices; the reused controls remain authoritative. The Hermes contribution and T3 MCP App use distinct native adapters; plain HTML rendering alone is not evidence of an answer callback. Explicit material attachment/import, native supporting-job orchestration and artifact presentation are now implemented in source; see docs/MATERIALS-JOBS.md. Automatic independent extraction actors and consolidated native/adaptive-teaching qualification remain distinct host obligations. This is not a qualified near-full-parity product yet.

## Local source checks

Node 24.12.x is required for built-in TypeScript stripping. Run `node --test --test-timeout=60000 test/*.test.mjs`. Tests create and clean synthetic temporary directories; no provider is called. No npm runtime dependencies or package installation are required when using the existing selected development toolchain. DOM controls require jsdom29.1.1 and host-compatible React/ReactDOM from that toolchain. Set task-local LH_TEST_TOOLCHAIN to its directory; do not install or choose a fallback implicitly.

Maintainer build: `node build.mjs <existing-Hermes-toolchain-directory>`. The reviewed build uses existing esbuild 0.28.2 and bundles a single ESM `desktop/plugin.js`; only Hermes SDK and host React imports remain. This does not install or load it. Review the built bytes and public manifest before delivery. Host/toolchain dependency security is a separate prerequisite; the Hermes contribution has no bundled npm runtime dependencies. The T3 stdio adapter loads the separately selected existing MCP SDK1.32.0, with no automatic dependency installation. DOM checks use the declared jsdom development version from an existing selected toolchain; installing dependencies is a separate action.

## Data and trust

Keep private configuration, raw state and exports outside the public source tree. Exported views omit active teacher commitments but can include learner answers, thinking, assessment and feedback: **redacted does not mean anonymous or public**. Raw teacher context includes commitments and must stay out of learner-facing directives. No credentials belong in either configuration or state.

A loaded Hermes desktop plugin is trusted application code, not a folder-only sandbox. The explicit folder picker limits this implementation's file API use, not all authority of JavaScript running in the app. Do not install an unreviewed bundle. Delivery acknowledgements mean composer delivery; only a returned authoritative revision proves persistence.
