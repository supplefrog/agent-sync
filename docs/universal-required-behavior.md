# Applying required behavior before governed work

Required behavior must shape the decision or action it governs, and the result must meet the user's intended outcome. This applies across task types. GitHub exposed the failure; it does not own the universal requirement.

The shared contract previously required completion and evidence but lacked a decision-time loading obligation. Hermes's native wording said to load relevant skills before replying, which does not establish loading before research or actions. Codex's relevance judgment likewise did not establish required pre-action application. The original failed conversation's exact load/search trace was unavailable, so this is a confirmed mechanism gap rather than a reconstructed causal trace.

`surfaces/core.md` now requires applicable owners and required references to finish before governed research, decisions or actions, excluding material already in context and unrelated procedures. It requires applying those requirements and checking the result against the intended outcome. Generated Codex AGENTS and Hermes SOUL overlays carry the shared rule. Domain procedures remain on demand.

For the reproduction, admitted `github-follow-up` description and focused-work routing provide access to Hermes's consolidated issue procedure. Its access reference is host glue, not a second issue policy. Duplicate checks precede a new-issue decision; known issue edits read the thread without restarting creation searches. The issue procedure assigns issue-specific corrections to its own reference and cross-task requirements to their canonical shared owner.

They add either no correction or avoidable ownership/runtime costs. This repair adds 222 bytes to each maintained host's selected standing units; no total-cost savings claim.
