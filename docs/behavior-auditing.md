# Behavior auditing

The user decides required behavior. Skills, instructions and tools are implementations whose value can change. Reconstruct an accumulated system's requirements from original decisions, current sources and observed outcomes; present concrete contract drafts and mismatches for clarification instead of asking the user to describe the whole system anew.

The existing `contracts/surface-matrix.json` owns optional `behavior_contracts`: trigger, desired and undesired outcomes, scope, applicable hosts, contraindications, acceptable native differences, owner paths, authority locator and observable checks. One contract can span several owners. Keep purpose/added-value/retirement metadata in `contracts/ownership.json`. These are maintenance records, not additional routine model prompts or a new admission authority. An authority label records a claim requiring its human source; schema validation does not authenticate approval. Empty exclusions are valid when no real exclusion exists. Unconfirmed drafts stay outside deployed requirements.

Run `python tools/run.py audit behaviors` for a read-only JSON coverage report, or use `--out PATH` to save it. The report binds its source metadata and lists missing/inferred/user-confirmed task-type records for admitted capabilities. System contracts cannot fill task-type gaps. Legacy skill prose and receipts can contain requirements even when typed metadata is absent; missing metadata is neither proof of uselessness nor permission to retire. This report covers recorded admitted owners, not every native tool, plugin, hook or memory path; inspect those through their existing owners when the audit scope includes them.

For each behavior cluster, record intended outcome, unique mechanisms, observed outcome, current mismatch or source-only risk, evidence identity/limits, and the next decision. Reuse historical evidence only for its bound claim. Inspect the current source, actual loading and causal mechanism before a costly probe. Known broken mechanics need direct reproduction and a valid nearby case. User-selected requirements do not require a benchmark to be legitimate. Uncertain instruction effects can use the existing `eval.py`, `eval_gate.py`, native/artifact lanes or instruction-retirement cache, choosing a lane that can exercise the claimed mechanism. No missing coverage cell automatically launches inference.

Matching files prove installation; mechanism checks prove their tested boundaries; observed task outcomes and appropriate comparisons support behavioral claims; rendered human selection owns taste. Preserve contradictory evidence. Record a useful uncertainty when those evidence levels cannot settle the decision. Apply authorized fixes and publication through the existing reconciler; contract metadata grants no new permission.
