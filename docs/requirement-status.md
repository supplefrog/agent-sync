## Native artifact evaluation and remaining outcomes

The [remaining-outcomes receipt](../evals/results/remaining-outcomes-20260927.json) links current mechanism, native artifact, blind-review, and governance measurements. Existing [evaluation runtime](../tools/evaluation_runtime.py), [artifact pilot](../tools/evaluation_artifact_pilot.py), and [Hermes worker](../tools/evaluation_hermes_worker.py) own this lane; it is not another admission authority.

The valid comparisons are one synthetic pair per task: handoff drafting tied, release copy tied, and a supported instruction proposal narrowly favored the baseline. Positive candidate runs prove a native typed `skill_view` body read; native catalog exposure matches between arms except for target presence. The near-miss records no target read but has no `read_file` path proof. The original protected `AGENTS.md` edit task encountered an incompatible native approval route in both arms and cannot count as comparative quality failure; the supported draft pair used a prospectively amended task. Execution used Hermes with GPT-6 Sol medium through the subscription route; provider-resolved identity was not independently verified. Codex readiness remains unverified after four failed writes. These results support neither statistical inference, model ranking, skill admission, nor full-host parity.

The evaluation retains matched runs, blind review, timing, and assertion discrimination from the inspected Claude mechanisms. It does not revive stale CLI/viewer rituals, force a winner, or treat missing metrics as zero. Source consistency checks alone do not authenticate a native run. Reuse only the recorded scope and current identity bindings.

## Targeted maintenance route

Start with the affected requirement above, then its owning source and linked evidence. Use [instruction-authoring](../skills/instruction-authoring/SKILL.md) for instruction content and [cross-agent-surface-engineering](../skills/cross-agent-surface-engineering/SKILL.md) for placement or deployment. Domain/tool owners retain executable interfaces. The registry determines admission state; it does not prove quality or authorize changes.

Read each receipt's claim, scope, source hashes, effective stack/runtime, and limitations before reuse. Existing evidence consistency checks validate recorded reports; independently bind the relevant current artifacts and runtime identities. Unchanged evidence can support its existing narrow claim. Changed source, runtime, harness, dependencies, contradictory findings, or invalidated assumptions reopen only the affected checks and neighbors.

Choose the smallest check that resolves the uncertainty: links/discovery for structural changes, a reproduced mechanism failure plus a nearby valid case for repairs, trigger/near-miss probes for selection changes, and matched baseline/candidate runs when a quality benefit is uncertain. Existing `eval.py --case` selects bounded probes; selected-case results must retain their limited scope.

Instruction retirement already has source/stack/suite/harness/validator-bound append-only receipt reuse. Its supported inline-text lane does not certify natural triggering or tool-bearing behavior; legacy, conflicting, mismatched, or unsupported evidence cannot authorize reuse. Preserve its owner and limits rather than adding another cache or ledger.

Reconcile only the authorized changes and demonstrated dependencies through the existing coordinator. Distinguish checked source, installed behavior, and verified publication. Update this map when a result changes its evidence/status; unrelated maintenance does not require refreshing every row or auditing the complete agent setup.
