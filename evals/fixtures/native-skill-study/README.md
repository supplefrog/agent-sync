# Bounded native skill study

Purpose-written scenarios, not sampled production work. `cases.json` holds identical arm prompts and hidden semantic criteria; `fixtures/` holds model-visible product inputs. `evaluated-owner/` preserves the tested skill, before the later reporting/readiness wording amendment. Do not present that amendment as quality-tested.

`oracle.py` checks necessary artifacts and source/link invariants. Its self-check deliberately accepts semantically poor artifacts; blind review supplies the quality judgment. `proposal_oracle.py` validates a replacement draft in its intended layout without applying it to the original fixture. The original protected-file pair remains incompatible, separate from the prospectively amended draft pair.

`blind-quality/` and `blind-proposal/` retain independently compared synthetic artifacts, source packets and acceptance criteria. Mapping files disclose arms only after review. Two valid pairs tied; the baseline was narrowly preferred in the draft pair. Both valid arms passed material criteria. This establishes no incremental skill advantage, statistical superiority, production fitness, model ranking or architecture-workflow parity.

See [receipt](../../results/remaining-outcomes-20260927.json) for observed tokens/time, frozen execution identities, discovery/body-read evidence and remaining limits. The exact-catalog setting was empty apart from the target skill; it was a bounded native catalog, not the user's complete fleet. Preserve that boundary when reusing the result.

Current Claude skill-creator mechanisms adapted into existing owners: paired realistic trials, independent blind comparison, separate correctness and semantic quality, timing/tokens and assertion discrimination. No third-party source code or fixed CLI/viewer procedure was copied.
